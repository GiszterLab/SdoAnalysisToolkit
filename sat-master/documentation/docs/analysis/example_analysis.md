# Example Analysis

## Overview:

Here, we show an example using the provided Object-Oriented Programing (OOP) MATLAB classes to set up a series of SDO Analysis. 

!!! warning Combatibility
    These OOP methods require MATLAB 2019A or newer for the parameter validation. If you are using older code, you can perform the SDO Analysis manually using the programatic methods.

## Processing Steps:
_This example is taken from the body of ```sdoAnalysis_demo_OOP.m```_

### Setup the Class Structures: 

1. Generate an instance of [xtDataCell](../classes/m_xtDataCell.md). 
~~~
xtdc = xtDataCell(); 
~~~

2. Populate the _xtDataCell_ with xtData

!!! note
    'xtData' here corresponds to a cell structure, as may be generated by _SAT.xtDataHolder_()

~~~
xtdc.import(xtData)
~~~

3. Assign _xtDataCell_ state-mapping parameters, as necessary:
!!! example
    ~~~
    xtdc.nStates = 20; 
    xtdc.stateMapping = 'log'; 
    ~~~

4. Assign State using definitions
~~~
xtdc.discretize(); 
~~~


5. Visualize the State Transform
~~~
xtdc.plot('dataField', 'stateSignal'); 
~~~
_This will plot the 'stateSignal' field of the xtDataCell, which is the definition of state, given the parameters, and what is used by the SDO for generating predictions_

!!! tip
    - SDOs work best when the distribution of state is either normal or uniform. (Which ensures a broad sampling of state around spikes) You can try out different parameters for state to find what works best for your signal. 
    - Extreme peaks in the signal can distort the sampling of state, as state is normally defined between minimum and maximum of the signal. 

6. Generate an instance of the [ppDataCell](../classes/m_ppDataCell.md)
~~~
ppdc = ppDataCell(); 
~~~

7. Populate the _ppDataCell_ with ppData. 

!!! note
    'ppData' here corresponds to a cell structure, as may be generated by _SAT.ppDataHolder_()

~~~
ppdc.import(ppData)
~~~

8. Generate Shuffled Spike Trains for Null Hypothesis Testing
~~~
ppdc = ppdc.shuffle(); 
~~~
!!! tip
    Shuffle will calculate the number of shuffles within the property ```ppDataCell.nShuffles``` field. 

### Setup the SDO Analysis Structures: 

1. Initialize an instance of [sdoMultiMat](../classes/m_sdoMultiMat.md)
~~~
smm = sdoMultiMat()
~~~

2. Compute the SDOs from the combination of [xtDataCell](../classes/m_xtDataCell.md) and [ppDataCell](../classes/m_ppDataCell.md)
~~~
smm = sdoMultiMat.compute(xtdc, ppdc)
~~~

!!! tip
    - There are multiple parameters which the ```.compute``` method can take, including the choice of algorithm, use of GPU, and how background is handled. 
    - There is also a setting to compute only a _range_ of channels from _xtDataCell_ and _ppDataCell_. This can be run for single components. 

### Visualize the SDOs

1. Find Significant SDOS
_Use significance tests to identify SDOs which are more likely to be interesting_

~~~
smm.findSigSdos(); 
~~~

→ This will populate the field ```sdoMultiMat.sigMat```, which is a structure including the number of tests used. 

2. Use the ```sdoMultiMat.plot``` method to visualize the SDOs, and associated measures. 
~~~
smm.plot(XT_CH_NO, PP_CH_NO)
~~~
_For whatever combination of xtChannel Number and ppChannel Number you are interested in._
!!! tip
    Use this plot method in combination with the ```.findSigSdos``` method to avoid blindly searching through multiple SDOs. 

### Test Predictive Utility of SDOs

1. Get the [predictionError](../classes/m_predictionError.md) class structure: 

~~~
predictionError = smm.getPredictionError(xtdc, ppdc, XT_CH_NO, PP_CH_NO)
~~~
!!! note
    This method provides an all-in-one call to return a _predictionError_ class. In the back-end code, however, this makes a call to the [pxtDataCell](../classes/m_pxtDataCell.md) class. 

2. Plot the PredictionError: 

~~~
predictionError.plot()
~~~

_This method provide a visual depiction of the SDO stats already performed in the ```predictionError``` class: You can access the stats directly from this element._
